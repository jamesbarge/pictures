# Scrape v2: tiered fetch, indies-first runner, horizon check, Claude Code review

**PR**: TBD
**Date**: 2026-11-05

## Changes
- **Restored `/scrape` and kept it from disappearing again.**
  - `.claude/` was gitignored, so the command, three rules files and the TMDB blocklist (`.claude/data-check-learnings.json`) only lived on the old machine.
  - `.gitignore` now ignores `.claude/*` except `commands/`, `rules/` and the learnings file.
  - `/scrape` is rewritten for the new pipeline and folds in `one <name>`, `review`, `status`, `report`, `resume` and `health`.
- **Tiered fetch** (`src/scrapers/fetch/tiered-fetch.ts`).
  - `BaseScraper.fetchUrl` goes direct first, then to Firecrawl (rawHtml, GB proxy) on a bot block: 403/429/503, `cf-mitigated`, or a Cloudflare interstitial title.
  - It fails soft with the original `HTTP <status>` error when there is no key or the per-run page budget (`SCRAPE_FIRECRAWL_MAX_PAGES`, default 300) is spent.
  - Firecrawl's LLM formats are never requested.
- **Browserbase tier** (`createRemoteBrowserPage` in `src/scrapers/utils/browser.ts`).
  - A hosted Chromium on a GB proxy, attached over CDP to the existing rebrowser-playwright, so there is no new dependency.
  - BFI tries it once after its local stealth attempts are blocked by Cloudflare. Capped by `SCRAPE_BROWSERBASE_MAX_SESSIONS` (default 10).
- **Tier usage is recorded.** It goes in `scraper_runs.metadata.fetchTiers` and `proxyUsed`, and in the run summary's `paidUsage`.
- **Runner** (`src/lib/jobs/scrape-all.ts`).
  - Independents (concurrency `SCRAPE_CONCURRENCY`, default 8, was 4) and chains (3) now run as two pools started together.
  - Independents are no longer queued behind the chains, and wall-clock time is the slower pool rather than the sum.
- **Unified pipeline** (`src/scripts/run-scrape-and-enrich.ts`). New phases:
  - **decisions**: re-applies `data/enrichment/manual-decisions.json`.
  - **rematch**: now default-on; `SCRAPE_REMATCH_SWEEP=0` disables it.
  - **posters**: `poster:audit --upcoming-only --execute`.
  - **horizon**: flags active cinemas under 30 days of listings.
  - **gaps**: writes `tmp/enrichment-gaps.json` for the Claude Code review, with TMDB candidates.
  - The summary also gains coverage before and after, short horizons and paid usage.
- **New scripts**: `npm run enrich:gaps` (`scripts/enrichment-gaps.ts`) and `npm run enrich:apply` (wraps `scripts/apply-manual-tmdb-matches.ts`).
- **Horizon fixes.**
  - Nickel asks for `limit=500`. Its API ignores paging and published 64 rows.
  - Coldharbour Blue follows `total_pages`.
  - Measured live: both venues currently publish short (to 29–30 Nov). Neither was a scraper cap.
- **Docs.** Close-Up comments and its error text no longer say "never a paid proxy". The scraping playbook has a new Scrape v2 section.

## Impact
- Venues blocked by Cloudflare (Close-Up; BFI on bad days) can be scraped on the first attempt instead of waiting for the block to clear. This needs the Firecrawl and Browserbase keys in `.env.local`.
- Full runs should finish faster, and independents land first.
- Enrichment judgement (TMDB matches, reclassifying stage broadcasts and events) is a repeatable step inside `/scrape`, not an ad-hoc session, and approved decisions survive re-scrapes.
- No schema migration: `fetchTiers` lives in the existing `scraper_runs.metadata` jsonb.
- The tiered-fetch unit tests cover escalation, challenge detection, budget, missing keys and JSON unwrapping.
